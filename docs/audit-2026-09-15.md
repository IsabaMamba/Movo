# Audit — 15 September 2026

Run against the branch that carries `0011`, `0012`, the inbox, the report queue and the
accessibility correction. Every claim below was checked against the schema in a throwaway
database or against the code, not against the docs. Where a doc disagreed with the code, the
doc is what was wrong.

Ordered by what can hurt somebody, then by what can silently rot.

## A. Security

### A1 · `activity_series` can still be written directly — the hole `0008` closed for `activities`

**Severity: high. Not on the roadmap under this description.**

`0008` revoked the direct `UPDATE` grant on `activities` because it let an organizer write
`joined_count`, `status` and `waitlist_count` straight through PostgREST — the numbers every
attendance claim is read from.

`activity_series` still has `activity_series_write`, a `FOR ALL` policy over a full
`insert, update, delete` grant. An organizer can `PATCH` their own series directly and change:

`price_minor` · `max_participants` · `local_start_time` · `weekday` · `location_id` ·
`duration_minutes` · `category_id` · `attributes` · `timezone`

Two consequences, both of which `0008` names as unacceptable for a single session:

1. **Price after the fact.** `0008` refuses to let an organizer change a session's price once
   people joined, calling it a bait-and-switch. The same organizer can change the series'
   price today, and every occurrence generated afterwards carries it.
2. **Silent divergence.** Changing a series does not touch the occurrences already generated
   from it, and nothing reconciles them. The series and its sessions drift apart with no
   error and no record.

**Fix:** `update_series()` and `cancel_series()` with `0008`'s locking rules, then revoke the
direct grant. Roadmap P1 · 10 asks for these as a _feature_ ("manage a series as a series").
It is also a permissions fix, and the revoke is the part that matters.

### A2 · `is_blocked()` has no test

**Severity: high.**

`docs/security.md` lists blocking as a control in place: _"symmetric and enforced in policy,
not in the UI — `is_blocked()` filters discovery, chat, and profile reads in both
directions."_

That predicate is called by `profiles_read`, `activities_read` and `nearby_activities()`, and
**nothing in the suite tests it.** If the symmetry is wrong in one direction, a blocked person
still sees their target's sessions, blocking silently does nothing, and the first sign is an
incident.

It is the single highest-value untested function in the repository: the safety control most
likely to be assumed working.

Also untested: `is_activity_organizer`, `is_activity_participant`, `is_community_member`,
`renumber_waitlist`. `sync_activity_counters` and `handle_new_user` are covered indirectly.

### A3 · Verified clean

- **Every `SECURITY DEFINER` function pins `search_path`.** All seventeen.
- **`staff` has no client grants** — confirmed absent from `role_table_grants` for both roles.
- **`0011` landed as intended:** `authenticated` holds `UPDATE` on `notifications.read_at` and
  on no other column.
- **Every table has RLS enabled.** `staff` is the only one with zero policies, correctly — it
  has no grant for a policy to refine.

## B. Correctness

### B1 · A database enum reached a person — fixed in this branch

`RosterScreen` told the organiser _"N personas quedaron como no_show"_ in the sentence
confirming the close-out. `no_show` is a column value. `STATE_LABEL` in the same file already
translates it. Fixed.

### B2 · A comment described code that changed three PRs ago — fixed in this branch

`SessionDetailScreen` carried _"No onPress yet … a hint here would describe a flow that does
not exist"_ above the report control. #29 wired reporting up on 13 September. The comment kept
being true-looking and being read. Fixed.

Both are small. Both are the same failure the repository has now had four times: **a
statement that was true when written and was not re-checked.** `docs/security.md` claimed a
deny-by-default that did not cover new tables; `docs/status.md` claimed Grupos was unbuilt and
got the table count, the route count and the voseo count wrong. It is worth naming as a
pattern rather than fixing case by case.

## C. Quality

### C1 · Zero JavaScript or TypeScript tests

**9,479 lines of client code. 14 screens. 0 test files.**

The SQL suite is genuinely good — twelve files, concurrency covered, RLS covered from both
sides. The client has nothing, and it contains pure functions that are trivially testable and
currently unverified:

| Function                       | Where                  | What breaks if it is wrong                   |
| ------------------------------ | ---------------------- | -------------------------------------------- |
| `densityOf` / `occupancyLabel` | `theme/heat.ts`        | An uncapped session reads as full            |
| `priceLabel`                   | `theme/index.ts`       | Money displayed wrong, silently              |
| `difficultyBand`               | `theme/index.ts`       | 1–5 mapped to the wrong word                 |
| `parseCoordinates`             | `lib/activities.ts`    | A venue lands in the wrong place             |
| `toInboxItem`                  | `lib/notifications.ts` | A notification renders as the wrong sentence |
| `validateAttributes`           | `lib/activities.ts`    | The schema-driven form accepts bad input     |

`parseCoordinates` is the sharpest: roadmap P1 · 9 already reports a venue whose latitude
exactly matches another venue 17 km away, which is the shape of a parsing bug. A test would
say whether it is.

### C2 · `toApiError` exists three times

`lib/activities.ts`, `lib/notifications.ts`, `lib/reports.ts`. Each new module copied it
because the original is module-private. Three copies of error mapping means three places a
Postgres error code stops being translated.

### C3 · The voice gap grew

**39 voseo occurrences across 14 files**, against a documented decision of neutral `tú`
(`docs/product.md`). It was 23 across 10 files on 8 September. Every screen added since made
it larger, because new copy matches the app rather than the doc.

This is a decision, not a defect — but it is a decision that costs more every week it stays
open. See roadmap P1 · 7.

## D. Process

### D1 · The default-privileges trap

Supabase's `alter default privileges in schema public grant all on tables to anon,
authenticated` is still in force, so **every table created after `0003` is world-readable on
creation.** `staff` was the first new table since, and the test asserting a normal user could
not read it failed. `docs/security.md` is corrected and `0012` revokes explicitly.

Every future migration that adds a table must `revoke all` on it and carry a test that says
so. Nothing else will notice.

### D2 · CI covers the database well and the client barely

The quality gate runs Prettier, ESLint and `tsc --strict`. Those catch syntax, style and
types. They caught none of: `accessibilityState` being dropped by `react-native-web`, a raw
enum in user copy, a stale comment, `toApiError` triplicated, or a wrong colour description in
an accessibility label.

That is not a criticism of the gate. It is the reason C1 matters.
